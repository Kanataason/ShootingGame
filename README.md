# SHOOTING GAME

C++ と DxLib で作った、2D の縦スクロールシューティングです。
敵の攻撃を避けて撃ちながら、矢印キーのコマンドを打ち込み、強化を選んで生き残ります。
ゲームエンジンを使わず、コンポーネント、ステートマシン、当たり判定、シーン管理などの基盤から自作しています。

**プレイ動画：** https://youtu.be/eP0z0dTtabU

## 遊び方

| 操作 | キー |
|---|---|
| 移動 | W / A / S / D |
| 撃つ | Enter(押している間、撃ち続ける) |
| 武器の切り替え | R |
| コマンド入力 | ↑ / ↓ / ← / → |
| 決定 | スペース(タイトル、結果画面) |
| 終了 | ESC |

1. Wave 1 から Wave 3 までを、時間いっぱい生き残ります。ウェーブが進むほど、敵の種類が増え、出る間隔が短くなります。
2. Wave 3 が終わると、ボスが出現します。
3. ボスは HP が 4 割を切ると、無敵の時間をはさんで、第二形態に移ります。
4. ボスを倒すとゲームクリア、プレイヤーの HP がなくなるとゲームオーバーです。

### ウェーブ
| ウェーブ | 長さ | 出る敵 |
|---|---|---|
| Wave 1 | 40 秒 | 狙い撃ちの敵 |
| Wave 2 | 50 秒 | + 反射弾の敵 |
| Wave 3 | 60 秒 | + 全方位の敵 |
| ボス | 倒すまで | ボス |

### コマンドと強化
- 5 秒ごとに、画面の上にコマンドの候補が 3 つ出ます。敵はそのまま動き続けます。
- 候補の 1 文字目(黄色の矢印)を打つと、その候補が選ばれます。残りの矢印を制限時間内に打ち切ると成功です。
- 打ち間違えると、最初からやり直しです。候補は無視してもかまいません。
- 同じ強化を重ねると段階が上がり(最大 Lv3)、矢印が長く、制限時間も長くなります(Lv1: 5 個・3.0 秒 〜 Lv3: 7 個・4.0 秒)。
- 強化の効果は 15 秒続きます。かけ直すと、残り時間が戻ります。

| 強化 | 色 | 効果(Lv1 / Lv2 / Lv3) |
|---|---|---|
| ATTACK | 赤 | 与えるダメージ ×1.25 / ×1.5 / ×1.8 |
| DEFENSE | 青 | 受けるダメージ ×0.8 / ×0.65 / ×0.6 |
| SPEED | 黄 | 移動速度 ×1.2 / ×1.4 / ×1.6 |
| PREDICT | 紫 | 敵の攻撃予告が、早く、はっきり見えるようになる |
| HEAL | 緑 | その場で HP が 5 回復する(段階なし) |

- 候補は 5 種類から、毎回ランダムに 3 つ選ばれます。HP が 3 割以下のときは、HEAL が必ず候補に入ります。
- かかっている強化は、機体のまわりのオーラと、機体の光る色でわかります。

### コンボ
- ATTACK と SPEED が両方かかっている間は、コンボになります。
- コンボ中は、**移動しながら撃つと** ダメージがさらに ×1.15 になります。止まって撃つと付きません。
- コンボ中は、機体が赤と黄色で交互に光ります。

### 攻撃予告
- 敵は撃つ少し前に、本体に向かって縮んでいく輪を出します。
- PREDICT の強化中は、撃つ方向の線も出ます。段階が上がるほど、早く(最大 1 秒前)、長く、濃くなります。
- 攻撃が切り替わった最初の 1 発は、予告を見る時間を作るために少し遅れて撃たれます。

### 武器
- **ロングショット**: 真上にまっすぐ、連射します。
- **拡散ショット**: 前方に、複数の弾をばらまきます。威力は高いですが、連射は遅めです。

### ヒートゲージ
- 撃つたびに、ヒートが溜まります。撃っていないと冷えます。
- 最大まで溜まると、オーバーヒートして、0 まで冷えるまで撃てなくなります。
- 押しっぱなしが一番強い状態にならないよう、「撃つ・止める」の判断が生まれるようにしています。

### 敵
| 敵 | 攻撃 | 出始めるウェーブ |
|---|---|---|
| 雑魚 1 | プレイヤーを狙って撃つ | Wave 1 |
| 雑魚 2 | 壁で跳ね返る弾を、扇状に撃つ | Wave 2 |
| 雑魚 3 | 全方位に弾をばらまく | Wave 3 |
| ボス | 狙い撃ち、反射弾、全方位を切り替える。第二形態では渦巻き弾が加わる | Wave 3 の後 |

## 技術的なポイント

### コンポーネント指向
`GameObject` に、`Movement`、`Attack`、`Status`、`Controller`、`Collider` などのコンポーネントを組み合わせて、プレイヤーや敵を作っています。

### ステートマシン
- プレイヤー、雑魚、ボスの行動を、イベント ID で状態を切り替える `StateMachine` で管理しています。
- どの状態からでも移れる遷移(死亡など)は、`AnyState` から登録します。
- 共通の処理は、基底クラスにまとめています。
  - `TimedState`: 一定時間たったら、次の処理へ移る(無敵、撃破演出)
  - `RandomMoveXState`: 左右のランダムな位置へ移動し続ける
  - `ShotState` / `PlayerShotState`: 一定間隔で撃つ。継承先は、撃ち方だけを書く
    - `ShotState` は、撃つ少し前に攻撃予告も出します。継承先は、撃つ方向を返す関数を 1 つ書くだけです。

ボスの状態遷移:

```
登場 → 第一形態 → (HP 40% 以下) → 無敵 → 第二形態
  └──────────── どこからでも ────────────→ 撃破
```

プレイヤーは、生存(通常、無敵、死亡)、攻撃(武器)、コマンドの 3 つのステートマシンを同時に動かしています。
コマンドの状態遷移:

```
待機 →(5 秒)→ 候補を表示 →(1 文字目を入力)→ 入力中
 ↑                  │(時間切れ)              │(成功、時間切れ)
 └──────────────────┴────────────────────────┘
どこからでも →(プレイヤーの死亡)→ 停止
```

「いつ」(候補を出す、成功したら強化をかける)はステートが決め、「どうやって」(入力の判定、強化の倍率)は `PlayerCommand` と `PlayerBuff` のコンポーネントが持ちます。

### コマンドと強化の作り
- `PlayerCommand`: 候補と、選ばれた矢印の進み具合を持ち、入力が合っているかを判定します。同時押しで順番が入れ替わって届いたときのために、0.05 秒の猶予を持たせています。
- `PlayerBuff`: 強化ごとの段階と残り時間を持ちます。倍率は段階から表で引くだけなので、攻撃や移動の処理は `GetAttackRate()` などを読むだけです。
- 攻撃予告の線と実際の弾は、`EnemyAttack` の同じ関数で方向を求めているので、予告と弾の向きがずれません。
- 敵はプレイヤーの強化を直接見ません。`GameScene` が予測の段階を `PlayerProvider` に入れ、敵はそこから読みます。
- `CharacterStatus` は、HP が変わったとき(`OnHealthChanged`)とダメージを受けたとき(`OnDamaged`)の通知を分けています。回復で無敵になったりしないようにするためです。

### データ駆動
敵の出現、ボス、シーン、音を、JSON で定義しています。ビルドし直さずに、調整できます。

| ファイル | 内容 |
|---|---|
| `JsonData/Scenes.json` | シーンの一覧と、置くオブジェクトのファイル |
| `JsonData/GameScene.json` | プレイヤーの設定 |
| `JsonData/Spawn.json` | ウェーブの長さと敵が出る間隔、雑魚敵のテンプレート(HP、攻撃、画像、当たり判定、出始めるウェーブ) |
| `JsonData/Boss.Json` | ボスの設定 |
| `JsonData/Sound.json` | 効果音と BGM のファイル、音量 |

### オブジェクトプール
弾 512 発分のメモリを最初に確保して、使い回しています。撃つたびのメモリの確保と解放をなくしています。

### そのほか
- **当たり判定**: 弾は太さを持った線分として、円や四角形と判定します。コライダー同士の押し戻しは、形の組み合わせごとの関数テーブルで呼び分けます。
- **Event(Observer)**: HP、ヒート、コマンド、強化の変化を、HUD に通知します。ゲームの処理と UI を分けています。
- **描画レイヤー**: 描画を登録だけして、最後にレイヤーの順(背景 → 敵 → プレイヤー → 弾 → エフェクト → UI)でまとめて描きます。
- **シーン管理**: 切り替えは予約だけして、フレームの最初に行います。切り替えるたびに JSON から作り直すので、リトライで最初の状態に戻ります。

## ビルド

### 必要なもの
- Windows 10 / 11(64bit)
- Visual Studio 2022(「C++ によるデスクトップ開発」)

DxLib と nlohmann/json は、リポジトリに入っています。別に入れる必要はありません。

### 手順
1. `ShootingGame.sln` を、Visual Studio で開きます。
2. 構成を **x64** の **Debug** か **Release** にして、ビルドします(Ctrl + Shift + B)。
   - x86(Win32)用の DxLib は入っていないので、x86 ではビルドできません。
3. 実行します(F5)。

- ビルドの後処理で、`JsonData`、`Library/image`、`Library/Sound` が、実行ファイルの隣にコピーされます。exe を直接起動しても動きます。
- JSON、画像、音だけを変えたときは、リビルドしてください(コードに変更がないと、コピーされないことがあります)。
- Release では、DxLib の `Log.txt` を出力しません。
