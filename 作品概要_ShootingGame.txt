2．動作環境

■ 実行環境
・OS　　：Windows 10 / 11（64bit）
・入力　：キーボード
・画面　：画面の大きさに合わせて、ウィンドウの大きさが自動で決まります。
　　　　　ウィンドウの端をドラッグして、大きさを変えることもできます。

■ 開発環境
・C++20
・DxLib 3.24f
・Visual Studio 2022（プラットフォームツールセット v143、x64）
・Windows 11

■ 動作確認
・ノートPC（Core i7-13620H / Windows 11 / 1920×1080）

■ 起動方法
「ShootingGame.exe」をダブルクリックしてください。
exe と同じフォルダに、「JsonData」「Library\image」「Library\Sound」が必要です。
終了は ESC キーで行えます。

■ ビルド方法
「ShootingGame.sln」を Visual Studio 2022 で開き、構成を x64 の Debug か Release にしてビルドしてください。
DxLib と nlohmann/json はリポジトリに入っているので、別に入れる必要はありません。
（x86 用の DxLib は入っていないので、x86 ではビルドできません。）

■ 操作方法
・移動　　　　　：W / A / S / D
・撃つ　　　　　：Enter（押している間、撃ち続ける）
・武器の切り替え：R
・コマンド入力　：↑ / ↓ / ← / →
・決定　　　　　：スペース（タイトル、結果画面）
・終了　　　　　：ESC

6．アピールポイント

■ ゲーム部分
コンセプトは「撃つ・止めるの判断が生まれるシューティング」です。
追加開発で、「敵の攻撃を避けながらコマンドを打ち込み、強化を選んで生き残る」遊びを加えました。

・コマンドで選ぶ強化
　5 秒ごとに、画面の上にコマンドの候補が 3 つ出ます。敵はそのまま動き続けます。
　候補の 1 文字目を打つと選ばれ、残りの矢印を制限時間内に打ち切ると成功です。
　打ち間違えると最初からやり直しになり、候補を無視してもかまいません。
　「今どの強化が必要か」と「避けながら打ち切れるか」の判断が生まれます。
・5 種類の強化
　攻撃（与えるダメージ増加）、防御（受けるダメージ減少）、速度（移動が速くなる）、
　予測（敵の攻撃予告がはっきり見える）、回復（その場で HP を 5 回復）があります。
　回復以外は 15 秒続き、重ねると最大 Lv3 まで上がります。段階が上がるほど矢印が長くなります。
　候補は毎回 5 種類からランダムに 3 つ選ばれ、HP が 3 割以下のときは回復が必ず入ります。
・攻撃＋速度のコンボ
　攻撃と速度が両方かかっている間は、移動しながら撃つとダメージがさらに 1.15 倍になります。
　止まって撃つと付かないので、「この組み合わせが常に正解」にならないようにしています。
・攻撃予告
　敵は撃つ少し前に、本体に縮んでいく輪を出します。予測の強化中は撃つ方向の線も出て、
　段階が上がるほど早く、長く見えるようになります。コマンドを打っている最中でも、
　避ける手がかりがあるようにしています。
・時間で進むウェーブ
　Wave 1（40 秒）、Wave 2（50 秒）、Wave 3（60 秒）と進み、ウェーブごとに敵の種類が増え、
　出る間隔が短くなります。Wave 3 が終わるとボスが出現します。

・ヒートゲージ
　撃つたびにヒートが溜まり、撃たずにいると冷えます。最大まで溜まるとオーバーヒートし、
　0 まで冷えるまで撃てなくなります。押しっぱなしが一番強い状態にならないようにしています。
・2種類の武器
　真上に連射する「ロングショット」と、前方に複数の弾をばらまく「拡散ショット」を、
　R キーで切り替えられます。
・攻撃の違う3種類の雑魚敵
　プレイヤーを狙って撃つ敵、壁で跳ね返る弾を扇状に撃つ敵、全方位に弾をばらまく敵がいて、
　この順にウェーブが進むと加わります。
・二段階のボス
　3 つのウェーブを生き残るとボスが出現します。ボスは HP が 4 割を切ると、無敵の時間をはさんで
　第二形態に移り、移動が速くなり、渦巻き弾が加わります。

■ プログラム部分
ゲームエンジンを使わず、C++ と DxLib で基盤から自作しています。

1．コンポーネント指向のゲームオブジェクト
　GameObject に Movement、Attack、Status、Controller、Collider などのコンポーネントを
　組み合わせて、プレイヤーや敵を作っています。オブジェクトの組み立ては GameObjectFactory が
　名前ごとの関数テーブルで呼び分けるので、新しい種類を足すときに既存の処理を変えずに済みます。
　（GameObject.h、Component.h、GameObjectFactory.cpp）

2．イベント ID で切り替える汎用ステートマシン
　持ち主の型をテンプレートで受け取るステートマシンを作り、プレイヤー、雑魚敵、ボスの行動を
　状態ごとのクラスに分けています。死亡のように「どの状態からでも」起きる遷移は AnyState から
　登録します。共通の処理は基底クラスにまとめ、継承先は違う部分だけを書いています。
　　- TimedState：一定時間たったら次へ移る（無敵時間、撃破演出）
　　- RandomMoveXState：左右のランダムな位置へ移動し続ける
　　- ShotState：一定間隔で撃つ。継承先は撃ち方だけを書く
　（StateMachine.h、TimedState.h、EnemyCommonStates.h、BossStates.h）

3．フリーリストを使ったオブジェクトプール
　弾 512 発分のメモリを最初に確保し、空きスロットをリストでつないで管理しています。
　取り出しと返却が一定時間で終わり、撃つたびのメモリの確保と解放がありません。
　配置 new で確保済みのメモリにオブジェクトを作り、返却時はデストラクタだけを呼びます。
　二重の返却や、別のプールのオブジェクトの返却は assert で検出します。
　その結果、弾が数百発出るボス戦でも、144FPS（モニターの上限）を下回らずに動いています。
　（ObjectPool.h、BulletManager.cpp）

4．太さを持った線分による弾の当たり判定
　弾を「太さを持った線分」として扱い、円とは最近点との距離、四角形とはスラブ法で判定しています。
　速い弾でも、すり抜けにくくなっています。コライダー同士の押し戻しは、形の組み合わせ
　（円と円、四角形と円、四角形と四角形）ごとの関数テーブルで呼び分け、逆向きの組み合わせも
　同じ表で処理します。
　（Collision.h、ColliderManager.cpp）

5．JSON によるデータ駆動
　シーンの構成、ウェーブ、雑魚敵のテンプレート（HP、攻撃、画像、当たり判定）、ボス、効果音と BGM を
　JSON で定義し、ビルドし直さずに調整できるようにしています。
　（JsonLoader.cpp、JsonData フォルダ）

6．ゲームの処理と UI の分離
　HP、ヒート、コマンド、強化の変化は Event（Observer パターン）で HUD に通知し、ゲームの処理が UI を
　直接触らないようにしています。描画は登録だけを行い、フレームの最後にレイヤーの順
　（背景 → 敵 → プレイヤー → 弾 → エフェクト → UI）でまとめて描きます。
　（Event.h、GameHUD.cpp、DrawManager.h）

7．安全なシーン切り替え
　シーンの切り替えは予約だけを行い、次のフレームの最初に実行します。処理の途中で
　シーンが消えることがありません。切り替えるたびに JSON から作り直すので、リトライで
　必ず最初の状態に戻ります。
　（SceneManager.cpp）

8．3 つのステートマシンを同時に動かすプレイヤー
　プレイヤーは、生存（通常・無敵・死亡）、攻撃（武器）、コマンド（待機・候補表示・入力中・停止）の
　3 つのステートマシンを同時に動かしています。移動しながら撃ち、同時にコマンドも打てます。
　「いつ候補を出し、成功したら何をするか」はステートが決め、「入力の判定」は PlayerCommand、
　「強化の段階と倍率」は PlayerBuff のコンポーネントが持ちます。倍率は段階から表で引くだけなので、
　攻撃や移動の処理は倍率を読むだけで済みます。
　（PlayerStates.cpp、PlayerCommand.cpp、PlayerBuff.cpp）

9．攻撃予告と実際の弾で、方向の計算を共通にする
　敵の撃ち方ごとに「弾が飛ぶ方向の一覧」を返す関数を作り、撃つときと予告を描くときで同じものを
　使っています。予告と実際の弾の向きがずれません。予告を出すタイミングは ShotState の基底クラスに
　まとめたので、雑魚もボスもすべての撃ち方に予告が付き、継承先は方向を返す関数を 1 つ書くだけです。
　敵はプレイヤーの強化を直接見ず、GameScene が予測の段階を PlayerProvider に入れて渡します。
　（EnemyAttack.cpp、EnemyCommonStates.h）

10．通知の分離
　HP が変わったとき（HP バーの更新）と、ダメージを受けたとき（被弾後の無敵）の Event を分けています。
　回復で HP が変わっても、無敵や点滅が起きません。
　（CharacterStatus.h、PlayerController.cpp）

11．その他
　・ウェーブの長さ、敵が出る間隔、敵が出始めるウェーブは Spawn.json で調整できます
　・deltaTime に上限を付け、ウィンドウ操作などで処理が止まった直後に弾や敵がワープしないようにしています
　・ウィンドウの大きさを、画面のタスクバーを除いた広さに合わせて自動で決めています
　・JSON の読み込み失敗などの例外を捕まえ、原因をメッセージボックスで表示してから終了します
　・各クラスが使うサービスを ServiceLocator にまとめ、グローバル変数を使わずに受け渡しています
